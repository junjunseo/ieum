# F4 정확도·성능·그래프 평가 준비

관련: [#28](https://github.com/junjunseo/ieum/issues/28), F4 [#21](https://github.com/junjunseo/ieum/issues/21).

## 현재 확보한 입력

`evaluation/manifest.json`에 입력 경로, 범주, 기대 종료 코드와 위반 종류별 건수를 기록했습니다.

| 범주 | 개수 | 구성 |
|---|---:|---|
| 정상 | 5 | 기본 계층, 공유 의존 다이아몬드, 분리된 구조, 정상·수정 데모 |
| 미선언 의존 | 2 | 하나·여러 미선언 대상 |
| 순환 | 3 | 자기·2개·3개 모듈 순환 |
| 계층 위반 | 4 | 직접 역행, 전이 계층 역행, 간접 의존 경로 역행, 복합 데모 |
| 잘못된 선언 | 1 | 중복·미선언 계층·자기 계층의 복합 입력 |
| 합계 | 15 | 정상 5개, 위반 10개 |

이는 기존 예제와 직접 작성한 초기 평가 입력입니다. 정상 데모와 수정 데모의 구조는 같으므로 독립 표본 15개로 해석하지 않습니다. 실제 프로젝트에서 추출한 corpus나 최종 정확도 결과는 아직 아닙니다.

## 재현 명령과 집계 기준

빌드 후 Python 3.9 이상에서 실행합니다. 추가 Python 패키지는 필요 없습니다.

```powershell
python scripts/evaluate.py
```

다른 빌드 경로는 `--ieum build/Release/ieum.exe`, 결과 위치는 `--output build/evaluation/results.json`으로 지정합니다. Ubuntu에서는 `--ieum build/ieum`을 사용합니다.

- 판정 단위: 입력 파일 하나. “위반 있음”을 양성으로 둡니다.
- TP: 위반 입력을 위반으로 판정. TN: 정상 입력을 정상으로 판정.
- FP: 정상 입력을 위반으로 판정. FN: 위반 입력을 정상으로 판정.
- 정확도: `(TP + TN) / 분류 가능한 입력 수`.
- 오탐률: `FP / (FP + TN)`. 미탐률: `FN / (FN + TP)`.
- 분모가 0이면 `null`을 기록합니다.
- 타임아웃, 프로세스 오류, 파싱 실패, 의미 검사 실패, 진단 누락은 미분류로 기록합니다. 미분류 입력을 TP로 세지 않으며 분류율·미분류 수를 함께 공개합니다.
- 별도로 종료 코드와 위반 종류·건수가 모두 일치해야 `exact_match`로 인정합니다. 하나라도 불일치하면 평가 명령은 종료 코드 1을 반환합니다. 설정·실행 도구 오류는 2입니다.
- 결과에는 OS, Python 버전, 실행 파일 SHA-256, manifest 및 입력별 SHA-256, 실제 진단을 저장합니다. 텍스트 해시는 BOM·줄바꿈 차이를 정규화합니다.

## 실제 corpus 수집 계획

| 후보 | 목적 | 수집할 정보 |
|---|---|---|
| 계층형 웹 서비스 구조 | 정상 분리와 하위→상위 역행 비교 | 원본 저장소·커밋, 모듈 대응표, 의존·계층 선정 근거 |
| 공유 저장소를 쓰는 여러 서비스 | 공유 의존과 순환 구별 | 합법 공유 경로, 변형한 간선과 기대 위반 |
| 플러그인·독립 도구 모음 | 분리된 컴포넌트와 미선언 참조 | 추출 범위, 제외 대상, 미선언 대상의 근거 |

수집 시 출처와 라이선스를 기록하고 구현 언어의 import를 Ieum 선언으로 옮기는 규칙을 먼저 고정합니다. 원본 정답과 단일 간선 변형 입력을 쌍으로 만들고, 서로 관련된 입력을 같은 평가 묶음에 둡니다. 기대 결과는 검사기 출력에서 복사해 만드는 대신 사람이 독립적으로 검토합니다. 후보 수집·정답 검토가 끝난 뒤 F4 최종 규모를 확정합니다.

## 성능 측정 조건

기존 [성능 기준선](PERFORMANCE_BASELINE.md)을 유지합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/benchmark.ps1 -ModuleCounts 50,100,200 -Iterations 11
```

- 같은 CPU·OS·컴파일러와 `-O2 -DNDEBUG` 조건에서 비교합니다.
- 50·100·200 모듈의 계층형 합성 입력, 워밍업 1회 후 11회 측정, 중앙값과 p95를 기록합니다.
- 측정 범위는 Lexer → Parser → Checker입니다. 의미 분석·함수 실행·DOT/SVG 생성·프로세스 시작은 포함하지 않습니다.
- corpus의 소스 크기·모듈 수·계층 수·의존 간선 수·깊이·반복 횟수를 보존합니다.
- CLI 평가 스크립트 실행 시간은 이 기준선과 비교하지 않습니다. 이후 실제 corpus 성능 평가용 실행기를 별도로 확장합니다.
- 현재 그래프 배치와 성능 최적화의 효과를 혼동하지 않습니다. 긴 계층 체인의 검사 비용은 남은 F4 과제입니다.

## 그래프 가독성 기준 초안

| 항목 | 이번 주 점검 기준 | F4 확장 |
|---|---|---|
| 소규모 | 대표 6종 및 데모 3종, 1366×900에서 노드 이름·방향·진단 판독 | 5·10 모듈에서도 같은 기준 적용 |
| 중규모 | 평가 입력 후보 확보 | 25·50 모듈, 확대·스크롤 후 임의의 경로 추적 가능 여부 기록 |
| 대규모 | 지원 성능을 아직 주장하지 않음 | 100·200 모듈의 렌더 시간·레이아웃 크기·겹침 조사 |
| 의미 일치 | 실제 DOT의 노드·간선·위반 강조와 SVG가 일치 | 독립 검토한 위반 경로와도 대조 |
| 구별 | 의존은 실선, 계층은 점선, 잘못된 노드는 텍스트 표식 | 색각 차이와 흑백 출력 점검 |
| 조작 | 예제 전환·계층 숨김·강조·확대·맞춤·SVG 저장 | 실제 사용자가 위반 근거를 찾는 시간 측정 |
| 좁은 화면 | 390px 너비에서 페이지 전체 가로 넘침 없이 사용 | 모바일 읽기·키보드 탐색 점검 |

화면 크기, 노드·간선·깊이, 렌더러 버전, 폰트, 확대율을 함께 기록합니다. 경로 찾기 시간의 합격선과 사용자 표본 수는 예비 사용자 평가 후 정하며, 아직 사용성 통과 수치를 주장하지 않습니다.
